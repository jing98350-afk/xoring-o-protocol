## 2. Contribution Principles

Please follow these principles when contributing.

### Human First

The protocol should focus on verified real-human presence and contribution.

### Privacy First

The protocol should avoid unnecessary exposure of raw biometric data.

Minimal proof is preferred.

For example:

```text
heartbeat_verified: true
```

is better than exposing full raw heart-rate data.

### Contribution First

The protocol should focus on real contribution, not speculation.

### No Financial Promises

Please avoid language related to:

- guaranteed income
- passive yield
- investment return
- staking profit
- gambling
- speculation
- financial promise
- profit sharing

### Open Discussion

The protocol is early.

Questions, criticism, and alternative proposals are welcome.

## 3. How to Submit an Issue

You can open an Issue if you want to:

- report a problem
- propose an idea
- suggest a use case
- improve a definition
- propose a data structure
- suggest a privacy principle
- suggest a compliance principle
- request a translation
- discuss a technical direction

When opening an Issue, please include:

```text
1. What are you proposing?
2. Which part of the protocol does it relate to?
3. Why does it matter?
4. What is the possible risk?
5. What is your suggested improvement?
```

---

## 4. How to Submit a Pull Request

Before submitting a Pull Request, please:

1. Read the related document.
2. Keep the language clear and direct.
3. Avoid speculative financial wording.
4. Explain what you changed.
5. Reference the related Issue if possible.

A good Pull Request should include:

```text
Summary:
- What changed?

Reason:
- Why is this change needed?

Scope:
- Which file or concept does this affect?

Risk:
- Does this introduce privacy, compliance, or interpretation risk?
```
